## 1. 产品命名

**MailHarbor**（邮件港湾 / 邮件码头）

- 隐喻：邮件像船，靠港后自动分拣、入库。比 "Auto Downloader" 更有产品感。
- 中文对外可叫 **「邮件收货助手」** 或 **「MailHarbor 邮件收货助手」**——对非技术老板更直白，避免"网点/系统"这类让人害怕的词。
- 备选名：`收件坞 · Dockflow`、`图稿收货台 · InkDock`。名字待客户定，设计稿先统一用 MailHarbor。

## 2. 这个软件到底在解决什么

### 2.1 现状（人工 3 步，每天重复几百次）
1. 客户把**定制图稿**打成 ZIP / TIF，发邮件到工厂邮箱（IMAP 收信），**标题写明品类**（如「原图+卡套」）
2. 操作员开邮箱，**一封封点开、下载、另存为**到对应品类的文件夹
3. 再**手动回一封信**告诉客户"收到"

### 2.2 痛点
| 痛点 | 后果 |
| --- | --- |
| 数量大、重复劳动 | 操作员一天几百次"下载-另存为"，人工成本高 |
| 靠人眼认标题归类 | 存错文件夹 → 上机时找不到图 → 延误生产 |
| 收到没回信 | 客户反复追问"收到没"，沟通成本高 |
| 时常漏件 | 图稿丢了要客户重发，体验崩 |
| 老板不在就停摆 | 业务被一个人卡住 |

### 2.3 软件带来的改变
> **邮件一进，自动按标题分拣、落到该去的文件夹、回信告诉客户"已收到"。**
> 人只需要"看概览 + 处理异常"。

## 3. 目标用户与使用场景

| 角色 | 特征 | 主要诉求 | 设计上怎么照顾 |
| --- | --- | --- | --- |
| **老板 斌** | 非技术、管经营、会加新品类 | 加关键词、看今天收了多少、别漏件、换邮箱 | 关键词自助增删、概览大数字、异常红点、邮箱参数表单 + 测试连接 |
| **操作员** | 天天用、追求快 | 快速找件、打开所在文件夹、重试失败 | 记录页可搜可筛、行内"打开文件夹"、一键重试 |
| **客户（外部）** | 不懂工厂内部 | 发完邮件安心；知道"被收到了" | 自动回信，语气专业，带文件名/数量 |

**使用节奏**：软件 7×24 挂在托盘 → 操作员上班先看概览的"昨日/今日收件 + 异常"→ 有异常才进记录页处理 → 老板偶尔加/停关键词。

## 4. 典型用户故事（驱动设计）

- **US1（最高频）**：客户 David 发来标题「原图+卡套」的邮件，附件 `POD_ORDER_20486.zip`。软件识别关键词 → 复制到 `D:\POD\生产\卡套\` 和 `E:\POD\备份\卡套\` → 回信 "Received, POD_ORDER_20486.zip (2 copies saved)"。操作员在概览看到 +1。
- **US2**：新品类"浴室垫"上线。老板在规则页点「新增规则」，填 `原图+浴室垫`、选 `D:\POD\生产\浴室垫`，保存即生效（不重启）。
- **US3**：某天 `E:` 盘掉线。软件照常把文件写到 `D:`，但记录里该条标"备份路径失败"，概览出现橙点；盘恢复后点"重试失败路径"，只补写 E 盘，D 盘不会重复。
- **US4**：邮箱密码换了导致 IMAP 登录失败。概览顶部出现"邮箱连接失败·请检查设置"横幅，点进账户页改密码并「测试连接」通过，期间不丢已下载记录。
- **US5**：客户标题写错成「原图+卡套+++」或「RE: 原图+卡套」。靠"去空格 + 忽略 RE 前缀"的匹配口径仍然命中（或按包含模式兜底）。
- **US6**：同一天两个客户都发 `design.tif`。第二个自动存为 `design (2).tif`，两人都收到回信。

## 5. 信息架构

```
MailHarbor（托盘常驻）
│
├── 01 概览 Overview ★落地页
│   ├── 监听状态（运行中 / 已暂停）+ 开始/暂停
│   ├── 今日：收件数 / 命中数 / 写入文件数 / 失败数
│   ├── 各目标磁盘剩余空间
│   ├── 邮箱健康 + 「连接失败·请检查设置」横幅
│   └── 最近 10 条记录（点击跳记录页）
│
├── 02 邮箱账户 Accounts
│   ├── 账户卡片列表（已启用 / 已停用 / 连接失败 / 待测试）
│   ├── 添加邮箱 → 服务商预设(Gmail/QQ/Outlook/自定义) + IMAP/SMTP 参数 + 测试连接
│   └── 编辑 / 测试连接 / 停用 / 删除
│
├── 03 触发规则 Rules ★核心
│   ├── 规则列表（预设 3 条｜启用开关｜命中次数｜最近命中｜搜索｜排序）
│   ├── 规则编辑（关键词 / 匹配范围 / 匹配方式 / 优先级）
│   ├── 目标路径 1~N（路径 / 剩余空间 / 必达开关 / 打开 / 删除 / 新增）
│   ├── 附件类型白名单
│   └── 是否自动回信 · 新增 / 删除 / 复制规则
│
├── 04 自动回复 Auto Reply
│   ├── 总开关 + 防轰炸设置
│   ├── 中 / 英文模板 + 变量插入 + 实时预览
│   └── 发送测试信
│
├── 05 下载记录 Records
│   ├── 表格（时间 / 账户 / 发件人 / 主题 / 命中规则 / 附件 / 大小 / 路径结果 / 状态）
│   ├── 筛选（状态 / 规则 / 时间）+ 搜索
│   └── 打开文件夹 / 按路径重试 / 导出 CSV
│
├── 06 设置（抽屉）
│   └── 开机自启 / 托盘 / 轮询间隔 / 日志 / 配置导入导出 / 版本
│
└── 托盘菜单：打开主界面 · 暂停监听 · 今日概览 · 打开存储目录 · 退出
```

## 6. 关键设计决策（与设计图对应）

| # | 决策 | 理由 | 图里在哪看 |
| --- | --- | --- | --- |
| D1 | **以"触发规则"为中心，而不是以"文件夹"为中心** | 客户心智是"什么类型的单进哪个夹子"，规则是业务单位；文件夹只是规则的一个属性 | 03-rules |
| D2 | **路径永远可见、可编辑、可一键打开** | 客户反复强调"把存储路径暴露出来" | 03-rules / dashboard |
| D3 | **一条规则的多路径用"路径 chip + 剩余空间"平铺**，不要折叠 | 客户特意点出"存 2 个路径"，必须一眼看到 2 个 | 03-rules |
| D4 | **记录页用"每路径一行小结果"表达扇出**（✔✔✖），不用长日志 | 非技术用户看符号最快，点开再看错误原因 | 05-records |
| D5 | **异常只上横幅/橙点，不弹模态框** | 7×24 常驻，弹窗会打断别的程序；但也绝不能静默 | dashboard / records |
| D6 | **邮箱参数表单 + 测试连接，不用 OAuth** | 客户明确要求用 SMTP；标准 IMAP/SMTP 参数（Gmail 应用专用密码 / QQ 授权码）比 OAuth 授权对非技术用户更直觉，也没有 Google 验证周期 | 02-accounts |
| D7 | **暖米白 + 墨蓝 + 朱红的"印刷工坊"气质** | 客户行业是印刷定制，工具要像"车间里的工单"，而不是通用 SaaS 后台 | tokens.css 全屏 |
| D8 | **全中文 + 大字号 + 1120~1440 布局自适应** | 操作员在车间看屏幕，字号小会看不清 | 全屏 |

## 7. 与 v0.1 的差异

v0.1 假设"所有附件进同一个固定文件夹"；v0.2 客户明确改为**按标题关键词分流，且一条关键词可落多个路径**。因此：
- 取消独立的「存储与下载规则」页，路径配置下沉到每条规则内部（默认路径作为兜底放在规则页底部/设置里）。
- 记录页、概览、验收清单全部改为"多路径结果"口径。
- 关键词维护成为 P0，必须有空的引导态（"还没有规则，先加一条"）。

## 8. 未定项（等客户拍板，见 REQUIREMENTS §9）

> v0.3 已定：**邮箱走 IMAP 收信 + SMTP 发信**（客户明确「用 smtp，不是授权」），不做 OAuth。界面用「服务商预设 + 手填参数 + 测试连接」代替授权向导。

影响设计的 3 个：关键词匹配口径（精确/包含）、未命中邮件是否留痕、兜底默认路径要不要。设计稿已按"默认精确匹配 + 未命中留痕可筛 + 提供兜底默认路径（默认关闭）"来做，若客户改口径，改动集中在这两处。

## 1. 一句话定义

一台**长期在线的 Windows 电脑**上运行的**邮件附件自动归档软件**：
盯着一个邮箱（IMAP 收信 / SMTP 发信）→ 按**邮件标题里的业务关键词**（如「原图+手机壳」）判断该不该存 → 把 ZIP / TIF 附件**自动下载到该关键词对应的一个或多个本地文件夹** → **自动回信**告诉客户"已收到"。

关键词由老板自己维护（预设 / 新增 / 删除），**不写死在代码里**。

## 2. 客户背景与场景

| 项 | 内容 |
| --- | --- |
| 行业 | POD（Print on Demand）定制，客户每天发送大量图片（ZIP 包 / TIF 大图） |
| 软件部署地 | 国外（因此用 Gmail 而非 QQ 邮箱） |
| 运行环境 | **Windows 电脑，长期开机不关机**（客户明确确认） |
| 使用者 | 工厂操作员 + 老板（斌）；非技术人员，要求"开机即用、不需要懂技术" |
| 竞品 | 朋友用 AI 写过一套同类工具（不模仿其界面，只求达到自己需要的效果） |

## 3. 业务核心：关键词规则（v0.2 新增，最重要）

### 3.1 客户原话
> "邮件标题：原图+手机壳 / 原图+卡套 / 原图+浴室垫
> 检测到邮件内容是这个标题的，就触发存储。这个关键词需要软件可以预设，可以新增和删除。"
>
> "有一个注意的地方：原图+卡套，同一份文件，如果存储 2 个本地路径"

### 3.2 需求拆解

| # | 需求 | 说明 |
| --- | --- | --- |
| K1 | **按邮件标题/内容匹配关键词** | 命中关键词才触发存储；未命中 → 标记"忽略"（默认策略是否记录待确认） |
| K2 | **关键词可预设** | 出厂预置 `原图+手机壳`、`原图+卡套`、`原图+浴室垫` 三条示例规则 |
| K3 | **关键词可新增 / 删除 / 启停** | 界面自助维护，无需改代码、无需重启 |
| K4 | **一条关键词 → 1~N 个本地路径** | 同一条规则可配置多个目标文件夹 |
| K5 | **同一份附件 → 复制到该规则的 N 个路径** | 如「原图+卡套」同时存到 `D:\生产\卡套` 和 `E:\备份\卡套`（多盘/网络盘备份） |
| K6 | **多路径进度独立可见** | N 个路径里某条失败，不能影响另一条；记录页要能看到"哪些路径已成功" |

### 3.3 匹配规则（工程口径，待客户确认）
- 默认匹配**邮件主题（Subject）**；可选同时匹配正文（Body）
- 默认**精确匹配去空格后的关键词**（`原图 + 卡套` 视同命中），并额外提供"包含匹配"开关（命中"原图+卡套"即算，即使前面有 `RE:`、`FWD:`）
- 大小写/全半角不敏感（`+` 与 `＋`、中英文括号归一）
- 规则可设**优先级**；一封邮件命中多条规则时：全部执行（推荐）或只按优先级最高一条（可配置）
- 关键词命中后，附件类型仍需在**白名单**（ZIP/TIF/TIFF/JPG/PNG/PDF）内才下载

### 3.4 规则的完整数据结构（界面与数据模型都按此设计）
```
规则 Rule
├─ 关键词 keyword          "原图+卡套"（可编辑）
├─ 是否启用 enabled        true
├─ 匹配范围 scope          subject | subject+body
├─ 匹配方式 mode           exact | contains
├─ 目标路径列表 targets[]
│    ├─ 路径 path           D:\POD\原图+卡套
│    ├─ 每路径可用空间显示（挂载点剩余）
│    └─ 是否必达 required   true=失败则整单算失败重试 / false=尽力而为
├─ 文件类型白名单 fileTypes [zip, tif, tiff]
├─ 是否自动回信 autoReply  true
└─ 统计 hits               累计命中的邮件数、文件数、最近命中时间
```

## 5. 隐含需求（客户没明说，但工程上必须有）

| # | 需求 | 理由 |
| --- | --- | --- |
| H1 | **去重**：同一封邮件不重复下载、不重复回信；**按"邮件 × 目标路径"粒度去重**（多路径场景下重试用） | 断线重连 / 重启后重复处理是最高频事故 |
| H2 | **失败可恢复**：哪条路径失败就只重试哪条，不重复写已成功的路径 | 客户图稿丢失 = 生产事故；重复写会让目标文件夹堆垃圾 |
| H3 | **断线重连 + 状态灯**：邮箱连不上/密码失效一眼可见 | 应用专用密码被改、网络抖动、企业邮箱禁用 IMAP 都会断，客户不看日志 |
| H4 | **回信模板可编辑 + 可关闭 + 防轰炸**（同线程只回一次） | 换号/重试时不能给客户连发多封 |
| H5 | **同名文件自动加序号不覆盖**；跨盘复制先写临时文件再原子改名 | 同一天多封同名 ZIP 很常见；防止客户拿到半截文件 |
| H6 | **安全**：Token 加密存储（DPAPI/keyring）、日志脱敏 | 账号被盗风险 |
| H7 | **可换电脑**：导出/导入配置（含规则） | 部署在国外，换机器要能快速迁移 |
| H8 | **历史记录**：时间/发件人/主题/命中哪条规则/存到哪些路径 | 客户对账、找件 |
| H9 | **首次配置引导**：邮箱参数填写向导（服务商预设 + 测试连接）+ 规则初始化向导 | 决定"能不能用起来" |
| H10 | **开机自启 + 单实例** | 电脑重启后无需人工干预 |
| H11 | **规则变更热生效**：改关键词/路径无需重启软件 | 老板随时会加新品类（新关键词） |
| H12 | **路径不可用时降级**：某个盘没插/掉线 → 只标该路径失败并持续告警，不阻塞其它路径 | 多盘/网络盘场景 |
| H13 | **磁盘空间监控**：每个目标路径的剩余空间在规则页可见 | 印刷大图很占空间，撑爆盘会静默丢件 |

## 6. 功能清单（MVP 范围）

### 6.1 核心流程（v0.2）
```
客户发邮件（标题含「原图+卡套」，正文写定制需求，附件 ZIP/TIF）
        │
        ▼
 [ IMAP 待命/轮询（IDLE + 兜底）] ── 发现新邮件
        │
        ├─ 标题/正文匹配关键词
        │     └─ 未命中 → 标记「忽略」（默认不下载；可选记录）
        ├─ 附件类型不在白名单 → 标记「忽略」
        ▼
 [ 命中规则：按规则的目标路径列表逐个复制 ]
        ├─ 路径 A：D:\POD\原图+卡套   ✔ 成功
        ├─ 路径 B：E:\备份\卡套       ✖ 失败 → 仅 B 进重试队列（A 不再重复写）
        ▼
 [ 全部必达路径成功后：自动回信「已收到，共 N 个文件」 ]
        │
        ▼
 [ 记录 + 托盘气泡通知 + 规则命中计数 +1 ]
```

### 6.2 页面/模块

| 模块 | 功能点 | 优先级 |
| --- | --- | --- |
| **1. 概览（Dashboard）** | 运行状态灯、邮箱健康、今日收件/命中数、失败与待重试、**各目标盘剩余空间**、最近记录、一键开始/暂停监听 | P0 |
| **2. 触发规则（★核心页）** | 关键词列表（含预设 3 条、搜索、启停、排序、拖拽优先级）；右侧规则编辑面板：关键词、匹配范围/方式、**目标路径 N 条（增删、浏览、打开、剩余空间、必达开关）**、附件白名单、是否自动回信、命中统计；新增/删除/复制规则；导入导出 | P0 |
| **3. 邮箱账户** | **手填邮箱参数**：服务商预设（Gmail / Google Workspace / QQ / Outlook / 自定义）→ IMAP 收件（主机/端口/SSL/账号/密码）+ SMTP 发件（主机/端口/SSL/账号/密码）→ **测试连接**（IMAP ✔ / SMTP ✔ 分别返回）→ 保存启用；账户列表状态（已启用/已停用/连接失败/待测试）、编辑、测试、停用、删除；密码用应用专用密码/授权码并加密存储 | P0 |
| **4. 自动回复** | 总开关、中/英文模板切换、变量插入（`{文件名}` `{数量}` `{关键词}` `{时间}`）、实时邮件预览、发送测试信、防轰炸设置（同线程只回一次 / 延迟 N 秒） | P0 |
| **5. 下载记录** | 时间/账户/发件人/主题/**命中规则**/附件/大小/**各目标路径结果（✔✔✖）**/状态，筛选、搜索、打开文件夹、按路径重试、导出 CSV | P0 |
| **6. 设置（抽屉/模态即可）** | 开机自启、最小化到托盘、轮询间隔、日志级别、配置导出/导入、版本与更新 | P1 |

> 原 v0.1 的「存储与下载规则」页已并入「触发规则」页；默认路径用于"未命中规则但仍在通用白名单内"的兜底策略（是否启用待确认，见 §8 Q3）。

### 6.3 非功能要求
- 常驻内存 < 200MB，CPU 空闲 < 2%
- 单附件建议上限 50MB；大文件复制显示进度
- 断网/休眠恢复后 30 秒内自动恢复监听
- 全中文界面，字号偏大，适配 1366×768 及 1920×1080
- 异常不弹窗打断（托盘通知 + 记录页）
- **多路径复制并发执行**，总耗时不应随路径数线性叠加到不可接受

## 7. 关键技术约束（影响设计与报价）

1. **邮箱采用标准协议，不走 OAuth**（客户 v0.3 明确）：**IMAP 收信 + SMTP 发信**，账号 + 应用专用密码/授权码。
   > 术语澄清（客户问过「SMTP 能不能收信、还用不用配 POP」）：**SMTP 只负责发信，不能收信**。收客户邮件必须另配收件协议——本项目用 **IMAP**（邮件留在服务器、手机端照常可见、新信近实时到达），**不配置 POP3**。POP3 若将来需要可单列可选，不影响本期。
   - Gmail：`imap.gmail.com:993 SSL` / `smtp.gmail.com:465 SSL`；密码必须用 **应用专用密码**（需先开启两步验证）。**不需要 Google Cloud 项目、不需要应用验证**——上线周期大幅缩短。
   - QQ 邮箱：`imap.qq.com:993` / `smtp.qq.com:465`，密码用邮箱设置里生成的**授权码**。
   - Outlook/365、企业邮箱同理（注意部分企业管理员会禁用 IMAP 或应用密码，需现场验证）。
   - 界面上提供**服务商预设**自动填主机端口，并保留"测试连接"按钮；这是整个软件最容易卡住的地方。
2. **多服务商支持**：通过 `MailProvider`/`MailTransport` 抽象，IMAP/SMTP 为唯一实现；配置项全部界面可改，不写死。
3. **部署在国外 Windows**：系统时区、非中文 Windows 字体、代理/网络波动。
4. **常驻**：本地 Web UI + 系统托盘（或 Qt），详见 `docs/ARCHITECTURE.md`。

## 8. 验收清单（Definition of Done）

- [ ] Windows 10/11 安装后开机自启，托盘常驻、无窗口打扰
- [ ] **发一封标题为「原图+卡套」的邮件，附件在 60 秒内出现在该规则配置的 2 个文件夹里**
- [ ] **标题改一个字（如「原图+卡」）→ 不触发存储**（精确匹配）；开启"包含匹配"后能触发
- [ ] **新增关键词「原图+卫衣」并配 1 个新路径 → 不改代码、不重启，下封邮件立即生效**
- [ ] **删除关键词 → 后续邮件不再入库**，历史记录仍可查
- [ ] **两条路径里关掉一个盘（模拟路径不可用）→ 另一条仍成功，失败那条在记录里标红并可单独重试**
- [ ] 同一封邮件不会被下载两次、不会回两封信
- [ ] TIF 附件同样落盘，重名自动加 `(2)`，不覆盖
- [ ] 客户收到回信，内容含文件名与数量
- [ ] 断网 5 分钟恢复后，期间到达的邮件能补下载
- [ ] 在界面里把 Gmail 参数改成另一个邮箱（或改应用专用密码），点「测试连接」通过后即生效；旧账号停用后不再收件
- [ ] Gmail 未开两步验证时，软件明确提示「需要应用专用密码」而不是笼统报密码错误
- [ ] 每条规则的命中计数、最近命中时间准确

## 9. 待客户确认的问题（Open Questions）

1. **关键词匹配口径**：标题"包含"即算（`RE: 原图+卡套` 也算），还是必须**完全一致**？（当前默认：去空格后精确匹配，`RE:`/`FWD:` 自动忽略；另有包含匹配开关）
2. **未命中的邮件**：直接忽略不记录，还是也在记录页留痕（便于排查"为什么没存"）？
3. **兜底默认路径**：是否需要"没有命中任何关键词但带 ZIP/TIF 附件的邮件，也存到一个默认文件夹"？（建议要，防漏件）
4. **多路径是"每条关键词各配"还是"全局路径池"**？（当前按"每条关键词各配 N 条路径"设计，最灵活）
5. **同一封邮件命中多条关键词**（如标题同时含「原图+手机壳」和「原图+卡套」）：全部执行还是只执行优先级最高一条？
6. **多路径存储方式**：是**复制多份**（每处一份实体文件），还是**软链接/快捷方式**？（复制更稳妥，占用多份空间）
7. **附件类型**：除 ZIP/TIF，是否收 JPG/PNG/PDF/PSD/AI？
8. **回信语言与内容**：英文还是中英双语？除"已收到"是否要承诺处理时效？
9. **同一封邮件多附件**：全部存同目录（重名加序号），还是每个附件单独建文件夹？
10. **是否需要把邮件正文（定制需求）也存成 txt 或写进记录**，方便跟单？
11. **关键词数量预期**：未来大概会有多少个品类关键词（10 / 50 / 200+）？影响界面是列表式还是搜索式。
12. 部署机器的系统版本、磁盘/盘符规划（例如 `D:` 放生产、`E:` 放备份）、是否 7×24 不休眠？
13. 交付形态：安装包 exe 还是绿色免安装？首次配置邮箱（应用专用密码/授权码）是否需要远程协助？
14. 预算与交付时间（用于决定 MVP 范围）。
